## 1. Overview

In this section, the **SkyLink Airline** React/Vite Frontend is built into static files and uploaded to **Amazon S3**.

Amazon S3 is used to store:

```text
HTML
CSS
JavaScript
Images
Static Assets
```

Deployment flow:

```text
SkyLink Frontend
      ↓
 npm run build
      ↓
    dist/
      ↓
 Amazon S3
      ↓
Static Website
```

---

## 2. Deployment Process

The SkyLink Frontend deployment process includes:

1. Build the React/Vite Frontend.
2. Create an S3 Bucket.
3. Configure the Bucket for website hosting.
4. Configure appropriate access permissions.
5. Upload the `dist/` directory.
6. Test the website in a browser.

---

## 3. Hands-on Practice

### 5.4.1. Create an S3 Bucket

#### Step 1: Build the Frontend

Open a Terminal in:

```bash
cd airline-frontend
```

Install dependencies if necessary:

```bash
npm install
```

Build the project:

```bash
npm run build
```

After a successful build:

```text
airline-frontend/
└── dist/
    ├── assets/
    ├── index.html
    └── ...
```

![Frontend Build](/images/5-Workshop/5.4-frontend-s3-cloudfront/frontend-build.png?v=2)

---

#### Step 2: Open Amazon S3

Open **AWS Management Console** → search for **S3** → select **Amazon S3**.

Select:

**Create bucket**

**Screenshot:**

```text
static/images/workshop/5-4/s3-console.png
```

![Amazon S3 Console](/images/5-Workshop/5.4-frontend-s3-cloudfront/s3-console.png?v=2)

---

#### Step 3: Configure the Bucket Name

Enter a globally unique Bucket name.

Example:

```text
skylink-airline-frontend-2026
```

Select the same Region used throughout the workshop:

```text
ap-southeast-1
```

> S3 Bucket names must be globally unique and cannot contain spaces.

![Create S3 Bucket](/images/5-Workshop/5.4-frontend-s3-cloudfront/create-bucket.png?v=2)

---

#### Step 4: Configure Access

Under **Block Public Access settings**, configure access according to the hosting approach used in this workshop.

For the **S3 Static Website Hosting** exercise, public access may need to be disabled.

AWS will display a warning before the change is applied.

> For the final SkyLink architecture, direct public access to S3 should be avoided where possible. **Amazon CloudFront** will be introduced later to provide a more secure architecture.

![S3 Public Access](/images/5-Workshop/5.4-frontend-s3-cloudfront/public-access.png?v=2)

---

#### Step 5: Create the Bucket

Keep the remaining settings as required and select:

**Create bucket**

After successful creation, the Bucket will appear in the S3 Bucket list.

**Checkpoint:**

```text
Bucket: skylink-airline-frontend-2026
Region: ap-southeast-1
Status: Created
```

---

#### Step 6: Upload the Frontend

Open the newly created Bucket → select **Upload**.

Upload the contents of:

```text
airline-frontend/dist/
```

Then select:

**Upload**

The Bucket should contain:

```text
S3 Bucket
├── assets/
├── index.html
└── ...
```
![Upload Frontend](/images/5-Workshop/5.4-frontend-s3-cloudfront/upload-files.png?v=2)

---

#### Step 7: Enable Static Website Hosting

Go to:

**Bucket → Properties → Static website hosting**

Select:

```text
Enable
```

Configure:

```text
Index document:
index.html
```

For a Single Page Application:

```text
Error document:
index.html
```

Select **Save changes**.

![Static Website Hosting](/images/5-Workshop/5.4-frontend-s3-cloudfront/static-website-hosting.png?v=2)

---

#### Step 8: Test the Website

After enabling Static Website Hosting, S3 provides a **Bucket website endpoint**.

Open the endpoint in a browser.

Expected result:

```text
SkyLink Airline
       ↓
React Frontend
       ↓
Website displayed successfully
```

**Screenshot:**

```text
static/images/workshop/5-4/skylink-s3-website.png
```

![SkyLink S3 Website](/images/5-Workshop/5.4-frontend-s3-cloudfront/skylink-s3-website.png?v=2)

---

#### Step 9: Verify the Uploaded Files

The S3 Bucket should contain the files generated by the Frontend build:

```text
index.html
assets/
    ├── *.js
    ├── *.css
    └── images/
```

The `src/` source directory should not be uploaded.

Only the **contents of `dist/`** should be deployed.

---

## 4. Expected Results

After completing this section, the SkyLink Frontend is hosted on Amazon S3.

Architecture at this stage:

```text
User
  ↓
S3 Static Website
  ↓
React/Vite Frontend
```

The deployment is successful when:

* The S3 Bucket is created successfully.
* The Frontend builds successfully.
* The contents of `dist/` are uploaded to S3.
* Static Website Hosting is enabled.
* `index.html` is configured as the index document.
* The SkyLink Frontend is accessible through the S3 Website Endpoint.

> **Note:** S3 is used directly in this step to demonstrate static website hosting. In the final architecture, **Amazon CloudFront** will be placed in front of S3 to improve HTTPS support, performance, content distribution, and security.
